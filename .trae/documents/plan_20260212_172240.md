## 计划：Webhook 配置状态功能权限控制系统

### 目标
实现基于 webhook 配置状态的功能权限控制，允许用户在未配置 webhook 的情况下使用基础前端功能，但限制第三方集成功能。

---

### 1. 修改配置检查逻辑 (checker.js)

将 webhook 从必填项改为可选：
- 修改 `checker.js` 中的 `checkDingtalkConfig` 方法
- 将 webhookBase 和 secret 的错误降级为警告
- 添加新方法 `isWebhookConfigured()` 返回配置状态

---

### 2. 创建权限控制模块 (permissions.js)

在 `chat-hub/src/` 创建 `permissions.js`：
```javascript
// 判断 webhook 是否已配置
function isWebhookConfigured() {
  return config.dingtalk?.enabled && 
         config.dingtalk?.webhookBase && 
         config.dingtalk?.secret;
}

// 受限功能列表
const RESTRICTED_FEATURES = {
  DINGTALK_INTEGRATION: 'dingtalkIntegration',
  WECHAT_INTEGRATION: 'wechatIntegration',
  BOT_AUTO_REPLY: 'botAutoReply'
};

// 检查功能是否可用
function isFeatureEnabled(feature) {
  if (!isWebhookConfigured()) {
    return false;
  }
  return true;
}
```

---

### 3. 后端 API 权限控制

修改以下 API 端点，添加权限检查：
- `/api/reply` - 机器人回复功能
- `/webhook/dingtalk` - 钉钉 webhook
- 其他第三方集成相关接口

添加中间件 `checkFeaturePermission`：
```javascript
function checkFeaturePermission(feature) {
  return (req, res, next) => {
    if (!isWebhookConfigured()) {
      return res.status(403).json({
        success: false,
        error: 'FEATURE_DISABLED',
        message: '该功能需要配置 webhook 后才能使用',
        configRequired: 'webhook'
      });
    }
    next();
  };
}
```
