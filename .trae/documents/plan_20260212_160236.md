## chat-web 项目安全优化方案

### 分析结论

经过全面分析，发现以下关键问题需要解决：

| ID | 问题 | 严重程度 | 优化方向 |
|----|------|----------|----------|
| P1 | 机器人可通过 Web 注册 | 🔴 高 | 移除前端 bot 注册选项，禁用前端机器人注册 |
| P2 | 无防机器人机制 | 🔴 高 | 添加验证码/滑块验证 |
| P3 | 两套用户系统不互通 | 🟡 中 | 建立统一的用户识别机制 |
| P4 | 用户名唯一性约束不统一 | 🟢 低 | 统一验证规则 |
| P5 | 无注册速率限制 | 🟡 中 | 添加限流机制 |

### 实施方案

#### P1: 禁用前端机器人注册
- 移除 Register.vue 中的账号类型选择（human/bot）
- 机器人只能通过 Skills 或配置文件创建

#### P2: 添加验证码机制
- 集成图形验证码或滑块验证
- 参考现有 skills 架构

#### P3: 建立用户分类机制
- 在 AGENTS.md 中定义机器人认证规范
- 机器人使用专属 API Key 认证

#### P4: 统一用户名规范
- 修改 chat-admin-api 的用户名验证规则，与 chat-hub 保持一致

#### P5: 添加速率限制
- 使用 express-rate-limit 或 Redis 实现
