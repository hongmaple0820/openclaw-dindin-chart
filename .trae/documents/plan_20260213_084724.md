## 详细技术方案：即时通讯系统架构分析

---

### 问题 1：私聊和群聊的数据传输处理模式

**当前架构分析：**

| 特性 | 群聊 (当前) | 私聊 (DM) |
|------|------------|-----------|
| 消息存储 | messages 表 | private_messages 表 |
| 传输方式 | Redis/SSE 广播 | Redis/SSE 广播 |
| 会话识别 | 无 (广播) | conversationId (user1_user2) |
| 消息处理 | 统一处理 | 独立处理 |

**方案结论：** 私聊和群聊可以采用相同的传输模式，区别在于：
- 群聊：广播给所有订阅者
- 私聊：基于 conversationId 路由给特定用户

### 问题 2：不使用 Redis 的纯 SSE 云端架构

**架构设计：**

```
┌─────────────┐     SSE      ┌─────────────┐
│  Instance A │◄────────────►│  Instance B │
│  (用户1)   │   HTTP/2     │  (用户2)   │
└─────────────┘              └─────────────┘
       │                          │
       ▼                          ▼
┌─────────────────────────────────────┐
│         SSE Cloud Gateway           │
│    (消息路由 + 实例发现服务)        │
└─────────────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────┐
│         消息队列 + 持久化            │
│       (数据库/文件存储)             │
└─────────────────────────────────────┘
```

**关键技术点：**
1. **实例注册**：每个实例启动时向 Gateway 注册
2. **消息路由**：Gateway 根据 conversationId 路由到目标实例
3. **消息持久化**：所有消息存储到共享数据库

### 问题 3：多实例部署场景下的功能实现

#### 3a) 跨实例、跨终端数据同步

**技术方案：**

```
┌─────────────────────────────────────────────────────────┐
│                    消息同步机制                          │
├─────────────────────────────────────────────────────────┤
│  1. 消息发布                                            │
│     POST /api/send → 存储DB → 发布到 Gateway           │
│                                                         │
│  2. 消息订阅                                            │
│     实例订阅自己关心的会话 (通过 SSE Gateway)            │
│                                                         │
│  3. 实时推送                                            │
│     WebSocket / SSE → 客户端                            │
└─────────────────────────────────────────────────────────┘
```

**实现细节：**
- 使用 Redis Pub/Sub 或自建 SSE Gateway
- 消息带 conversationId，会话订阅制
- 离线消息存储到数据库

**数据流程图：**

```
┌──────────────┐     创建会话      ┌──────────────┐
│   客户端     │─────────────────►│   实例 A     │
└──────────────┘                  └──────┬───────┘
                                         │
                                         ▼
                                  ┌──────────────┐
                                  │  会话服务    │
                                  │ (会话管理)  │
                                  └──────┬───────┘
                                         │
              ┌──────────────────────────┼──────────────────┐
              │                          │                  │
              ▼                          ▼                  ▼
       ┌──────────────┐         ┌──────────────┐    ┌──────────────┐
       │  私聊路由    │         │  群聊路由    │    │  消息存储    │
       │ (A↔B)       │         │ (广播)       │    │ (DB)         │
       └──────────────┘         └──────────────┘    └──────────────┘
```

**会话表设计：**

```sql
-- 会话表
CREATE TABLE sessions (
  id TEXT PRIMARY KEY,
  type TEXT,              -- 'private' | 'group'
  participants TEXT,      -- JSON数组
  name TEXT,              -- 群名称
  created_by TEXT,
  created_at INTEGER,
  updated_at INTEGER,
  metadata TEXT            -- JSON扩展字段
);

-- 群成员表
CREATE TABLE group_members (
  session_id TEXT,
  user_id TEXT,
  role TEXT,              -- 'owner' | 'admin' | 'member'
  joined_at INTEGER,
  PRIMARY KEY (session_id, user_id)
);
```

### 总结

当前系统已具备基本的多实例能力 (TransportManager 支持 Redis/SSE)，扩展方向：
1. **纯 SSE 方案**：自建 SSE Gateway 替代 Redis
2. **会话隔离**：增加 conversationId 路由
3. **安全传输**：消息签名 + TLS
