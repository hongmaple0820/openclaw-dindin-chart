# 会话指令解析规则

> 版本: 1.0.0
> 规范 ID: `command-parsing`

本文档定义了 Agent 解析会话指令的规则和规范。

---

## 1. 指令类型

### 1.1 直接指令

明确的、带有目标的指令。

```
@小琳 帮我查询天气
小琳，发送消息到群里说"大家好"
```

**特征**：
- 明确提及 Agent 名称
- 明确的动作词
- 清晰的意图

### 1.2 隐式指令

不直接提及，但意图明确的指令。

```
有人知道今天天气吗？        # 隐式请求天气
这个文件怎么打开？          # 隐式请求帮助
```

**特征**：
- 问题形式
- 隐含请求帮助
- 需要上下文理解

### 1.3 延续指令

对之前对话的延续。

```
好的，继续
然后呢？
再说详细点
```

**特征**：
- 简短
- 关联上文
- 需要会话历史

    ├─────────────────────────┐

    ▼                         ▼
┌──────────────┐      ┌──────────────┐

## 3. 解析规则

### 3.1 目标识别

#### @ 提及

```
正则: @(\S+)
示例: @小琳 帮我查天气
结果: target = "小琳"
```

#### 名称提及

```
关键词: Agent 名称列表
示例: 小琳帮我查天气
结果: target = "小琳"
置信度: 0.9
```

#### 代词指代

```
规则: 指向最后一个活跃的 Agent
示例: 它怎么样？（指向上一个回复的 Agent）
```

### 3.2 动作识别

#### 动作词表

| 动作类别 | 动作词 | 示例 |
|---------|--------|------|
| 查询 | 查、查查、查询、搜索、找 | 查天气 |
| 发送 | 发、发送、说、告诉、通知 | 发消息 |
| 创建 | 创建、新建、添加、增加 | 创建任务 |
| 删除 | 删除、移除、取消 | 删除任务 |
| 修改 | 修改、更新、编辑、改 | 修改设置 |
| 执行 | 执行、运行、做、帮 | 执行脚本 |

#### 动作优先级

```
1. 明确动词 > 隐含动词
2. 第一个动词 > 后续动词
3. 否定动词 (不、别) 取消动作
```

### 3.3 参数提取

#### 时间参数

```
规则: 识别时间表达式
示例: 明天早上9点
结果: { time: "2026-03-08T09:00:00", timezone: "Asia/Shanghai" }
```

#### 数量参数

```
规则: 识别数字和单位
示例: 发送3条消息
结果: { count: 3 }
```

#### 目标参数

```
规则: 识别目标对象
示例: 发送给小明
结果: { target: "小明" }
```

### 3.4 置信度计算

```
confidence = base_confidence
           + target_match_bonus      # 目标匹配加成
           + action_match_bonus      # 动作匹配加成
           + context_relevance_bonus # 上下文相关性加成
           - ambiguity_penalty       # 歧义惩罚

分数范围: 0.0 - 1.0
阈值:
  - >= 0.8: 高置信度，直接执行
  - 0.5 - 0.8: 中置信度，确认后执行
  - < 0.5: 低置信度，请求澄清
```

## 4. 上下文处理

### 4.1 会话上下文

```typescript
interface SessionContext {
  // 会话信息
  sessionId: string;
  channel: string;
  
  // 最近消息
  recentMessages: Message[];
  
  // 活跃 Agent
  activeAgents: string[];
  
  // 未完成任务
  pendingTasks: Task[];
  
  // 用户偏好
  userPreferences: Record<string, any>;
}
```

### 4.2 上下文应用

```
1. 目标消歧: 根据 activeAgents 确定默认目标
2. 参数补充: 从 recentMessages 提取缺失参数
3. 意图推断: 结合 pendingTasks 推断隐式意图
4. 格式调整: 根据 userPreferences 调整输出格式
```

## 5. 多 Agent 协作

### 5.1 路由规则

```
1. 明确目标 → 路由到指定 Agent
2. 能力匹配 → 路由到有该能力的 Agent
3. 负载均衡 → 路由到空闲 Agent
4. 默认路由 → 路由到默认 Agent
```

### 5.2 协作模式

#### 顺序协作

```
用户: 帮我查天气并发送给小明
解析: [查询天气] → [发送消息]
执行: Agent A 查天气 → Agent B 发送消息
```

#### 并行协作

```
用户: 让小琳和小猪都帮忙想想
解析: [小琳思考] + [小猪思考]
执行: 两个 Agent 同时执行
```

#### 条件协作

```
用户: 如果明天下雨就提醒我
解析: [条件判断] → [条件成立时提醒]
执行: 监控条件 → 触发提醒
```

## 6. 错误处理

### 6.1 解析失败

```typescript
interface ParseError {
  type: 'unknown_target' | 'unknown_action' | 'missing_param' | 'ambiguity';
  message: string;
  suggestions: string[];
  confidence: number;
}

// 示例
const error: ParseError = {
  type: 'unknown_target',
  message: '未找到名为"小芳"的 Agent',
  suggestions: ['小琳', '小猪'],
  confidence: 0.3
};
```

### 6.2 处理策略

| 错误类型 | 处理策略 |
|---------|---------|
| unknown_target | 提示可用 Agent 列表 |
| unknown_action | 询问用户意图 |
| missing_param | 请求补充参数 |
| ambiguity | 列出候选选项让用户选择 |

## 7. 解析示例

### 示例 1: 直接指令

```
输入: @小琳 帮我查询北京明天的天气

解析结果:
{
  type: "direct",
  target: "小琳",
  action: "query",
  params: {
    query_type: "weather",
    location: "北京",
    time: "2026-03-08"
  },
  confidence: 0.95
}
```

### 示例 2: 隐式指令

```
输入: 这个问题怎么解决？

上下文: 上一个消息讨论了编程问题

解析结果:
{
  type: "implicit",
  target: null,  // 使用默认或上一个活跃 Agent
  action: "help",
  params: {
    topic: "programming",
    context: "上一个讨论的编程问题"
  },
  confidence: 0.7
}
```

### 示例 3: 延续指令

```
输入: 再详细点

上下文: 上一个回复是关于天气查询的结果

解析结果:
{
  type: "continuation",
  target: "上一个回复的 Agent",
  action: "elaborate",
  params: {
    topic: "上一个话题"
  },
  confidence: 0.85
}
```

## 8. 配置参数

```typescript
interface ParserConfig {
  // 置信度阈值
  confidenceThreshold: {
    high: 0.8,    // 直接执行
    medium: 0.5,  // 确认后执行
    low: 0.3      // 请求澄清
  };
  
  // 上下文窗口
  contextWindow: {
    maxMessages: 10,    // 最大消息数
    maxTimeMs: 3600000  // 最大时间跨度（1小时）
  };
  
  // 超时设置
  timeout: {
    parse: 1000,   // 解析超时（毫秒）
    execute: 30000 // 执行超时（毫秒）
  };
}
```
