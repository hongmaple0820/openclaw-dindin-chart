## 1. 产品定位与愿景

### 1.1 产品定义
**MapleClaw** 是一个多 Agent + 多人类的协同办公平台，定位于"AI驱动的下一代团队协作中枢"。

### 1.2 产品愿景
> "让 AI 与人类无缝协作，就像呼吸一样自然。"

### 1.3 核心价值主张
- **人机共生**: 打破人类与AI的界限，构建自然协作的工作流
- **智能协同**: 多Agent自主协作，自动完成复杂任务
- **开放生态**: Skill/MCP插件体系，无限扩展能力边界
- **统一入口**: 类似钉钉的All-in-One办公协作体验

### 1.4 目标市场
- **初期**: AI/开发者社区、小型敏捷团队
- **中期**: 中小企业数字化办公升级
- **长期**: 企业级协同办公平台

## 2. 目标用户画像

### 2.1 核心用户类型

#### 用户类型 A：开发者/AI专家
| 维度 | 描述 |
|------|------|
| 背景 | 技术背景深厚，熟悉AI工具和API |
| 痛点 | 多个AI助手分散，难以协同；缺乏与团队的集成 |
| 需求 | Agent自定义、Skill开发、工作流编排 |
| 使用场景 | 代码审查、文档生成、自动化测试 |

#### 用户类型 B：产品经理/项目负责人
| 维度 | 描述 |
|------|------|
| 背景 | 业务导向，需要高效协调团队 |
| 痛点 | 信息分散、需求跟踪困难、AI工具使用门槛高 |
| 需求 | 项目群管理、任务看板、AI辅助决策 |
| 使用场景 | 需求评审、项目规划、会议纪要 |

#### 用户类型 C：普通团队成员
| 维度 | 描述 |
|------|------|
| 背景 | 多元技能，需要日常协作支持 |
| 痛点 | 工具学习成本高，重复性工作多 |
| 需求 | 简单易用的AI助手、自动化任务处理 |
| 使用场景 | 日程管理、信息检索、文档协作 |

### 2.2 用户场景示例
```
场景1：智能项目管理
产品经理在群聊中："@项目助手 创建一个新项目：官网重构"
Agent自动：创建项目群 → 初始化任务看板 → 邀请相关人员 → 设置里程碑提醒

开发者在群聊中分享代码，@代码审查员

场景3：跨时区协作
团队成员异步工作，Agent根据成员时区自动调度任务 → 
生成每日站会摘要 → 推送关键事项给相关成员
```

## 4. 核心功能模块详细设计

### 4.1 通信系统

#### 4.1.1 群聊系统
**功能目标**: 支持多人类和多Agent在同一群聊中协作

**功能清单**:
| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 创建群聊 | 支持人类创建、Agent自动创建 | P0 |
| 群成员管理 | 邀请、移除、设置管理员 | P0 |
| 消息类型 | 文本、图片、文件、引用、@提及 | P0 |
| 消息同步 | 多端实时同步、历史消息加载 | P0 |
| 群消息策略 | 轮次限制、话题终结检测 | P1 |
| 群分组 | 项目群、普通群、系统群分类 | P1 |

**技术关键点**:
- WebSocket + SSE 双通道实时通信
- Redis Pub/Sub 消息广播
- SQLite 消息持久化 + FTS5全文搜索

#### 4.1.2 私聊系统 (DM)
**功能目标**: 支持点对点私密通信

**功能清单**:
| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| 发起私聊 | Human-Human, Human-Agent | P0 |
| 会话列表 | 最近会话、未读计数 | P0 |
| 消息状态 | 已发送、已送达、已读回执 | P0 |
| 消息搜索 | 单聊消息全文搜索 | P1 |
| 消息加密 | 端到端加密（可选） | P2 |

#### 4.1.3 消息同步与离线机制
**功能清单**:
- 在线状态检测（心跳机制）
- 离线消息队列（断线重连后同步）
- 消息确认机制（ACK）
- 多端登录同步策略

### 4.2 Agent 系统

#### 4.2.1 Agent 接入层
**设计原则**: Agent通过Skills链接接入，而非硬编码

**功能清单**:
| 功能点 | 描述 | 优先级 |
|--------|------|--------|
| Agent注册 | 配置化注册，支持动态加载 | P0 |
| Skills链接 | 通过URL/本地路径加载Skills | P0 |
| MCP集成 | 支持MCP Server接入 | P0 |
| Agent绑定 | Agent与Human用户绑定关系 | P0 |
| 身份认证 | API Key认证、OAuth2.0 | P0 |

**Agent接入方式**:
```
方式1：配置文件接入
{
  "agents": [
    {
      "name": "小琳",
      "type": "claude",
      "skills": ["./skills/coding", "https://hub.skills/sql-master"],
      "mcpServers": ["filesystem", "github"],
      "owner": "maple"
    }
  ]
}

方式2：手动添加（UI）
1. 在Web界面选择"添加Agent"
2. 选择Agent类型（Claude/OpenAI/本地模型）
3. 配置Skills和MCP
4. 分配权限和可见性

方式3：内置Agent快速加入
1. 系统预设常用Agent模板
2. 一键添加到指定群组
3. 自动完成初始化配置
```

#### 4.2.2 Agent 生命周期管理
```
状态机：
Created → Configured → Online → Working → Offline → Archived
           ↓              ↓         ↓          ↓
        配置 Skills    心跳检测   任务执行   超时断开
```

**功能清单**:
- Agent状态监控（在线/离线/忙碌）
- 心跳检测机制
- 自动重连策略
- Agent资源配额管理（并发、速率限制）

#### 4.2.3 Agent 工作状态系统
**工作状态流转**:
| 状态 | 触发条件 | 可见性 |
|------|----------|--------|
| Idle | 无任务时 | 公开 |
| Listening | 在群中监听消息 | 公开 |
| Processing | 处理任务中 | 公开 |
| Thinking | 深度思考模式 | 群成员可见 |
| DoNotDisturb | 手动设置或系统调度 | 公开 |
**功能点**:
- 状态自动切换（基于任务队列）
- 状态指示器（UI显示）
- 忙碌时消息排队策略
- @提醒优先级处理

### 4.3 关系系统

#### 4.3.1 好友系统
**关系类型**:
| 关系类型 | 描述 | 功能 |
|----------|------|------|
| Human-Human | 人类之间好友 | 私聊、互看动态、协作权限 |
| Human-Agent | 人类与Agent | 专属Agent、私聊、授权管理 |
| Agent-Agent | Agent间关系 | 工作流协作、能力调用 |

**功能清单**:
- 好友搜索与添加（按用户名、ID）
- 好友分组（自定义分组）
- 好友动态（工作状态、最近在忙）
- 好友权限设置（谁可以@我、私聊权限）

#### 4.3.2 角色系统
**角色定义**:
| 角色 | 权限范围 | 适用场景 |
|------|----------|----------|
| Owner | 全部权限 | 群主、项目Owner |
| Admin | 管理权限（除Owner专属） | 群管理员 |
| Member | 基本权限（发言、查看） | 普通成员 |
| Guest | 受限权限（仅查看、有限发言） | 临时参与者 |
| Bot | 特殊权限（API调用、自动触发） | Agent |

**权限模型（RBAC）**:
```
权限层级：
Org Level → Project Level → Group Level → Channel Level

权限类型：
- 读权限: 查看消息、成员列表
- 写权限: 发送消息、创建内容
- 管理权限: 邀请/移除成员、设置配置
- 超级权限: 删除、Owner专属
```

### 4.4 Skills 系统

**设计原则**: 可插拔、声明式、版本化管理

#### 4.4.1 Skill 定义与规范
```yaml
# Skill 描述文件 (skill.yaml)
name: code-reviewer
version: 1.0.0
description: 代码审查助手
author: mapleclaw-team

# 能力声明
capabilities:
  - code_analysis
  - security_scan
  - performance_review

# 依赖
dependencies:
  - mcp:filesystem
  - mcp:github

# 触发条件
triggers:
  - keywords: ["@代码审查", "review this"]
  - fileTypes: [".ts", ".js", ".py", ".go"]

# 配置项
config:
  strictness: "medium"  # low/medium/high
  autoComment: true
```

#### 4.4.2 Skill 市场
**功能清单**:
| 功能 | 描述 | 优先级 |
|------|------|--------|
| Skill 浏览 | 分类浏览、搜索、热门标签 | P1 |
| Skill 安装 | 一键安装、依赖自动解析 | P1 |
| Skill 发布 | 开发者上传、版本管理 | P1 |
| Skill 评分 | 用户评价、使用统计 | P2 |
| Skill 推荐 | 基于使用习惯推荐 | P2 |

#### 4.4.3 Skill 运行时
- 沙箱隔离执行（安全）
- 资源配额限制（CPU、内存、网络）
- 热加载/热卸载
- Skill 间通信机制

### 4.5 MCP 系统 (Model Context Protocol)

**设计目标**: 统一外部服务接入标准

#### 4.5.1 MCP Server 类型
| 类型 | 示例 | 用途 |
|------|------|------|
| 文件系统 | filesystem | 本地/远程文件访问 |
| 代码仓库 | github, gitlab | 代码管理、PR Review |
| 数据库 | postgres, mysql | 数据查询、分析 |
| API 服务 | slack, notion | 第三方服务集成 |
| 自定义 | 企业内网服务 | 私有化部署 |

#### 4.5.2 MCP 配置
```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/workspace"],
      "env": {}
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}
```

#### 4.5.3 MCP 权限控制
- 细粒度权限（读/写/执行）
- 按 Agent 授权
- 审计日志

### 4.6 记忆系统

**设计目标**: 让 Agent 拥有长期记忆，实现个性化服务

#### 4.6.1 记忆类型
| 类型 | 存储内容 | 保留策略 |
|------|----------|----------|
| 短期记忆 | 当前会话上下文 | 会话结束清除 |
| 长期记忆 | 用户偏好、历史决策 | 永久存储 |
| 工作记忆 | 任务执行状态 | 任务完成清除 |
| 共享记忆 | 团队知识库、项目文档 | 团队共享 |

#### 4.6.2 记忆存储架构
```
┌─────────────────────────────────────┐
│         Memory Manager              │
├─────────────────────────────────────┤
│  Vector DB (语义检索)               │
│  ├─用户记忆嵌入                     │
│  └─知识库嵌入                       │
├─────────────────────────────────────┤
│  Relational DB (结构化记忆)         │
│  ├─用户偏好                         │
│  └─历史决策记录                     │
├─────────────────────────────────────┤
│  Cache (热点记忆)                   │
│  └─Redis 缓存                       │
└─────────────────────────────────────┘
```

#### 4.6.3 记忆检索策略
- 语义相似度检索（Vector Search）
- 时间衰减权重（近期记忆优先）
- 相关性评分（上下文匹配）
- 记忆压缩（定期归档旧记忆）

### 4.7 会话管理

#### 4.7.1 会话类型
| 类型 | 描述 | 特点 |
|------|------|------|
| 群聊会话 | 多人多 Agent 协作 | 广播模式、消息同步 |
| 私聊会话 | 一对一交流 | 私密、端到端 |
| 任务会话 | 临时任务执行 | 短生命周期、结果导向 |
| 系统会话 | 系统通知、日志 | 只读、归档 |

#### 4.7.2 会话状态管理
```
会话状态：
Active → Paused → Archived → Deleted

状态说明:
- Active: 活跃会话，实时同步
- Paused: 暂停会话，保留上下文
- Archived: 归档会话，可检索
- Deleted: 软删除，可恢复（30 天）
```

#### 4.7.3 会话上下文
- 上下文窗口管理（Token 限制）
- 上下文摘要（长会话压缩）
- 上下文切换（多会话并行）

### 4.10 心跳系统 + Hooks 系统

#### 4.10.1 心跳机制
```
心跳流程:
Agent ──heartbeat──> Server ──ACK──> Agent
  │                      │
  │ 超时未响应           │ 记录状态
  ▼                      ▼
标记离线              触发告警
```

**配置参数**:
| 参数 | 默认值 | 说明 |
|------|--------|------|
| heartbeatInterval | 30s | 心跳间隔 |
| heartbeatTimeout | 90s | 超时阈值 |
| maxRetries | 3 | 重试次数 |

#### 4.10.2 Hooks 系统
**Hook 类型**:
| Hook 点 | 触发时机 | 用途 |
|--------|----------|------|
| onMessageReceived | 收到消息 | 消息过滤、自动回复 |
| onTaskCreated | 任务创建 | 自动分配、通知 |
| onAgentOnline | Agent 上线 | 初始化、状态同步 |
| onAgentOffline | Agent 离线 | 任务转移、告警 |
| onUserJoin | 用户加入 | 欢迎消息、权限设置 |

**Hook 配置**:
```yaml
hooks:
  - event: onMessageReceived
    handler: "auto-tag-messages"
    conditions:
      - group: "项目群"
      - contains: "@todo"
    action: "create_task"
```

#### 4.11.1 项目工作流阶段

**完整 9 阶段流程**:
```
需求发掘与整理 → 产品设计 → UI设计 → 架构规划 → 开发部署 → 测试 → 产品验证 → 上线部署 → 运营推广
```

**智能灵活协调**:
| 能力 | 说明 |
|------|------|
| 阶段并行 | 需求+技术调研、UI+API设计、前端+后端开发 |
| 阶段跳过 | 小改动可简化流程 |
| 阶段回溯 | 需求变更可回到需求阶段 |

#### 4.11.2 工作流阶段与 Skills 映射

| 阶段 | 核心Skills | 主要输出 |

#### 4.11.5 质量门禁

**代码提交门禁**:
- ESLint 通过
- TypeScript 无错误
- 提交信息规范

**合并门禁**:
- 代码评审通过
- 测试通过
- 无冲突

**发布门禁**:
- 功能完整
- 测试覆盖率 > 80%
- 性能达标
- 安全通过

#### 4.11.6 工作流定义
```yaml
workflow:
  name: "代码发布流程"
  version: "1.0"
  trigger:
    type: "manual"  # manual/scheduled/event
  steps:
    - id: code_review
      name: "代码审查"
      agent: "code-reviewer"
      timeout: 3600
      
    - id: run_tests
      name: "运行测试"
      agent: "test-runner"
      dependsOn: ["code_review"]
      
    - id: deploy
      name: "部署"
      agent: "deploy-bot"
      dependsOn: ["run_tests"]
      condition: "tests.passed == true"
```

## 5. 竞品分析

### 5.1 竞品概览

| 竞品 | 定位 | 优势 | 劣势 |
|------|------|------|------|
| **钉钉** | 企业协同办公 | 生态完善、用户基数大 | AI 能力弱、扩展性差 |
| **飞书** | 智能协作平台 | 产品体验好、集成度高 | AI 功能有限、封闭生态 |
| **Slack + AI** | 团队沟通 + AI | 插件生态丰富 | AI 集成分散、体验割裂 |
| **Microsoft Teams** | 企业协作 | Office 集成、企业级 | 笨重、AI 能力一般 |
| **Discord + Bots** | 社区 + 机器人 | 机器人生态活跃 | 非办公场景、管理弱 |

### 5.2 差异化定位

| 维度 | MapleClaw | 传统协同工具 |
|------|-----------|-------------|
| **AI 原生** | AI 是一等公民，深度集成 | AI 是附加功能 |
| **Agent 生态** | 开放 Skill/MCP 市场 | 封闭/有限插件 |
| **人机协作** | 人类与 Agent 平等协作 | 人类主导，AI 辅助 |
| **可扩展性** | 声明式配置，无限扩展 | 固定功能集 |
| **记忆能力** | 长期记忆，个性化服务 | 无记忆或弱记忆 |

### 5.3 SWOT 分析

**优势 (Strengths)**:
- AI 原生架构设计
- 开放的 Skill/MCP 生态
- 灵活的人机协作模式
- 轻量级、易部署

**劣势 (Weaknesses)**:
- 品牌知名度低
- 生态建设初期
- 企业级功能待完善

**机会 (Opportunities)**:
- AI 协同办公市场快速增长
- 企业对 AI 工具接受度提高
- 开源社区支持

**威胁 (Threats)**:
- 大厂快速跟进 AI 功能
- 技术迭代快，需持续投入
- 数据隐私合规要求
